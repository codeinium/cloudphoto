# Сценарий проверки и скринкаста (до 5 минут)

Подготовьте каталог `photos` с файлами `IMG.JPG`, `img.jpg`, `Фото 100%.jpeg`,
а также `ignore.png` и вложенным каталогом с фотографией.
В `photos-small` оставьте только `IMG.JPG`. Создайте пустой каталог `downloaded`.
Настройте переменные окружения заранее; секреты в видео не показывайте.

1. Покажите историю: `git log --oneline --reverse`, затем `make linux`.
2. `cloudphoto list` — пустой архив либо ранее созданные альбомы.
3. `cloudphoto upload --album 'Лето 2026' --path photos` и
   `cloudphoto list --album 'Лето 2026'` — только JPEG, регистр сохранён.
4. Повторите upload после изменения одного файла; скачайте альбом:
   `cloudphoto download --album 'Лето 2026' --path downloaded`.
   Сравните исходные JPEG и скачанные файлы командой `cmp`.
5. Создайте альбом `Пустой` из `photos-small`, удалите из него `IMG.JPG`.
   В `list` альбом остаётся, `list --album 'Пустой'` ничего не выводит.
6. Выполните `cloudphoto mksite`, откройте `https://photos.vvotNN.itiscl.ru/`.
   Покажите обе страницы альбомов, галерею, кириллическое имя и пустой альбом.
   Откройте несуществующий URL для проверки `error.html`.
7. Удалите одну фотографию через `delete --album ... --photo ...`, проверьте список.
   Удалите альбом целиком, повторите `mksite` и обновите сайт.
8. Покажите ошибки: несуществующий альбом, `cloudphoto upload` без `--album`,
   пустой исходный каталог. После каждой команды выполните `echo $?` (должно быть 1).
   `(unset BUCKET; cloudphoto list)` проверит ошибку окружения.

Для демонстрации пустого фотоархива удалите оставшиеся альбомы и повторите `mksite`.
При повторной демонстрации используйте тестовые альбомы, которые можно удалять.
