# cloudphoto

CLI на Go с Cobra для фотоархива в Yandex Object Storage.
Решение [домашнего задания № 1](https://docs.itiscl.ru/vvot/2026-2027/hw/hw01/).

## Сборка и проверка

Нужны Go 1.25.4 или новее и Git. Для инфраструктуры — Terraform >= 1.5
и доступ к Yandex Cloud. Приложение не требует установленного AWS CLI.

```sh
git clone https://github.com/codeinium/cloudphoto.git
cd cloudphoto
go mod download
make build
make test
make vet
make linux
```

`bin/cloudphoto` — программа для текущей ОС; `bin/linux-amd64/cloudphoto` —
самостоятельный исполняемый файл для Linux x86_64. Для запуска на Linux:
`./bin/linux-amd64/cloudphoto list`.

## Облачная инфраструктура

Сначала выполните практические задания по Cloud DNS и Certificate Manager:
нужны существующая зона `vvotNN.itiscl.ru` и выпущенный сертификат на
`vvotNN.itiscl.ru` и `*.vvotNN.itiscl.ru`.

Terraform создаёт сервисный аккаунт, назначает ему `storage.admin` для работы
CLI (включая настройку политики и хостинга), выпускает статический ключ,
создаёт бакет с HTTPS и CNAME `photos` в существующей зоне.
Сайт работает непосредственно через Object Storage.

```sh
export YC_TOKEN="$(yc iam create-token)"
cp terraform/terraform.tfvars.example terraform/terraform.tfvars
# Заполните folder_id, bucket_name, domain, cert_id, dns_zone_id.
terraform -chdir=terraform init
terraform -chdir=terraform validate
# Если CNAME сайта уже существует, один раз импортируйте его перед plan:
# terraform -chdir=terraform import yandex_dns_recordset.photos '<dns_zone_id>/photos.<domain>./CNAME'
terraform -chdir=terraform plan
terraform -chdir=terraform apply
```

`YC_TOKEN` читает провайдер; токен не записывается в конфигурацию.
Для операций S3 конфигурация использует созданный статический ключ; для Cloud API
(каталог, IAM и HTTPS) — `YC_TOKEN`.
Аккаунту, которому принадлежит токен, нужны права на создание сервисных аккаунтов
и ключей, назначение роли в каталоге, управление Object Storage, DNS и использование
выбранного сертификата. При ошибке IAM проверьте разрешения этого аккаунта.

| Переменная | Пример / значение |
| --- | --- |
| `folder_id` | ID вашего каталога |
| `bucket_name` | `photos.vvotNN.itiscl.ru` |
| `domain` | `vvotNN.itiscl.ru` |
| `cert_id` | ID выпущенного сертификата |
| `dns_zone_id` | ID существующей DNS-зоны |

В условии описание `dns_zone_id` противоречит названию параметра: там указан FQDN.
Здесь это именно ID зоны, который требует API Cloud DNS. Полное имя сайта выводится
из `domain`: имя бакета должно быть `photos.<domain>` для прямого хостинга
на собственном домене в Object Storage.

Статический ключ хранится в Terraform state. State, локальные переменные и секреты
исключены из Git. Файл `.terraform.lock.hcl` следует хранить в репозитории.
Terraform не удаляет непустой бакет автоматически (`force_destroy` выключен).

## Переменные окружения приложения

После `terraform apply`:

```sh
export BUCKET="$(terraform -chdir=terraform output -raw bucket_name)"
export AWS_ACCESS_KEY_ID="$(terraform -chdir=terraform output -raw aws_access_key_id)"
export AWS_SECRET_ACCESS_KEY="$(terraform -chdir=terraform output -raw aws_secret_access_key)"
```

Все три значения обязательны и должны быть непустыми. Конфигурационного файла
у программы нет. Регион `ru-central1` и endpoint `https://storage.yandexcloud.net`
заданы в коде. По требованию задания проверка окружения выполняется при каждом
запуске, в том числе перед показом справки.

## Команды

```sh
./bin/cloudphoto list
./bin/cloudphoto upload --album 'Лето 2026' --path ./photos
./bin/cloudphoto list --album 'Лето 2026'
./bin/cloudphoto download --album 'Лето 2026' --path ./downloaded
./bin/cloudphoto delete --album 'Лето 2026' --photo 'IMG_001.JPG'
./bin/cloudphoto delete --album 'Лето 2026'
./bin/cloudphoto mksite
```

Каталог для `download` должен существовать. Для `upload` и `download` по умолчанию
используется текущий каталог. Загрузка находит только обычные файлы `.jpg` и `.jpeg`
без учёта регистра расширения и без обхода вложенных каталогов. Альбом и имена
файлов сравниваются с учётом регистра; `/` в именах альбомов и фотографий запрещён.
Повторная загрузка заменяет фотографию с тем же исходным именем.

Удаление последней фотографии сохраняет пустой альбом. Удаление без `--photo`
удаляет фотографии и сам альбом. Команда `list` сортирует исходные имена по байтам
UTF-8, включая кириллицу; пустой список ничего не выводит.

`mksite` настраивает публичное чтение объектов через ACL бакета и политику доступа, а также хостинг
с `index.html` и `error.html`, затем публикует страницы по шаблонам задания.
Публичное правило разрешает только `s3:GetObject`. Существующие правила управления
сохраняются: в Yandex Cloud политика только с публичным чтением блокирует
остальные операции даже для аккаунтов с IAM-ролями. Для бакета без политики
`mksite` также добавляет управление текущим статическим ключом и доступ через
консоль. Terraform явно сохраняет управление для сервисного аккаунта `cloudphoto`.
Веб-страницы обновляются явным повторным запуском `mksite` после изменения архива.
Галерея Galleria использует внешние скрипты и стили из шаблона задания.

```sh
./bin/cloudphoto mksite
terraform -chdir=terraform output -raw site_url
```

Доступность HTTPS после привязки сертификата может появиться с задержкой;
см. [документацию Yandex Cloud](https://yandex.cloud/ru/docs/storage/operations/hosting/certificate).

Данные выводятся в stdout, ошибки — в stderr. При успехе код возврата 0,
при ошибке — 1. Ошибочные аргументы дают `Ошибка в аргументах`, отсутствие
переменных — `Не заданы переменные окружения`. Ошибки S3 не скрываются.

## Организация хранилища

`E(x)` — `url.PathEscape(x)` из стандартной библиотеки Go, обратимое кодирование
одного компонента ключа; для имён `.` и `..` точки дополнительно кодируются как
`%2E`, чтобы браузер не нормализовал путь. Регистр, кириллица, пробелы, `%`
и другие символы сохраняются.

| Объект | Ключ |
| --- | --- |
| Маркер альбома (пустое тело) | `albums/E(альбом)/` |
| Фотография | `photos/E(альбом)/E(исходное имя файла)` |
| Главная страница | `index.html` |
| Страница ошибки | `error.html` |
| Страница альбома | `album{N}.html`, начиная с 1 |

Маркер хранит существование альбома независимо от количества фотографий.
Разные префиксы исключают пересечение фото и служебных страниц. Одинаковые имена
фотографий в разных альбомах имеют разные ключи. Альбом создаётся при первой
непустой загрузке; неудачный перенос после создания маркера может оставить
пустой или частично заполненный альбом. Повторный запуск завершает загрузку.

Списки S3 обходятся с пагинацией. Перед выводом декодируются и сортируются исходные
имена, поскольку сортировка закодированных ключей может отличаться от UTF-8 имён.
При генерации страниц каждый компонент уже закодированного ключа кодируется ещё
раз для URL: например, `%20` в ключе становится `%2520` в ссылке. Это позволяет
браузеру запросить именно сохранённый ключ. Тексты и атрибуты экранируются для HTML.
Загрузка на диск использует временный файл и rename после полного получения,
чтобы не портить существующий файл при ошибке передачи.

Номера страниц определяются заново по сортированным именам при каждом `mksite`.
Старые `album{N}.html` за пределами нового списка остаются в бакете, но больше
не связаны с главной страницей; требование удаления таких страниц в задании отсутствует.

## Структура и тесты

- `cli.go` — команды Cobra, флаги и проверка аргументов.
- `storage.go` — клиент S3, схема ключей и пагинация.
- `archive.go` — операции с фотоархивом и публикация сайта.
- `site.go` — HTML по шаблонам задания.
- `terraform/` — инфраструктура.

Тесты используют локальный HTTP-сервер с S3-ответами и настоящий AWS SDK:
проверяют загрузку, замену, скачивание, удаление, пустые альбомы, пагинацию,
UTF-8 сортировку, URL/HTML-экранирование, ошибки доступа и разбор аргументов.
Ключи и облачные ресурсы для них не нужны. Проверка реального облака выполняется
после развёртывания по [сценарию демонстрации](docs/demo.md).
GitHub Actions запускает тесты, vet, Linux-сборку и Terraform validate.
